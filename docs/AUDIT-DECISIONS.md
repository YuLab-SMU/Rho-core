# 对审核报告的取舍

输入是用户提供的 [原始审核报告](review/USER-REPORT.md)。报告对减少自建模块提出了
有用方向，但没有给出可以逐项追溯的引用，也没有建立报告中“当前实现”与本项目源码
的证据映射。以下是本项目的工程判断；报告中的前沿、性能与安全结论不直接作为事实。

## 采用、修正与后置

| 报告建议 | 本项目的决定 | 原因与验证 |
| --- | --- | --- |
| 减少模块、网关和中间件 | 采用：从一个本地工具调用路径开始 | 复杂度必须由具体工作需要证明；测量往返、故障面与维护成本 |
| 将 QuerySnapshot 合入模型上下文 | 修正：不建设快照存储，仍按需读真实 Owner | 上下文可保留读过的材料，无法证明当前文件或会话未改变；用外部改盘验证 |
| 用工具框架替代 OperationGateway | 修正：复用标准调用表达，保留必要受理与结果关联 | 框架名称不能保证原生效果、重试与并发写入；用重复送达和中断实验验证 |
| 默认向量检索、原始账本与派生记忆视图 | 后置到实际检索需求；记忆归外部调用方 | 首个科学工具流程不需要向量库，执行记录也不是对话记忆 |
| 用模型循环取代独立 Planner | 采用责任边界：规划由外部 Agent 提供 | Core 向人和 Agent 提供同一能力，不建设另一个推理运行时 |
| 多 Agent 依需加入 | 留在外部运行时 | 先证明单个调用方能闭合工作，再决定额外协作是否有价值 |
| Serverless、分布式事件流与弹性云 | 近期不引入 | 本地单用户需求未证明云设施必要；有实测规模问题再选择 |
| 零信任隔离、OpenShell 与静态扫描 | 作为具体部署的候选机制 | 需要明确隔离对象、平台与被验证行为，不能仅凭产品名宣称安全 |
| 日志可以审计和回滚 | 修正：日志帮助定位，回滚依赖实际 Owner | 原生副作用并不随日志撤销；取消、恢复字节和重新执行分别验收 |
| 推理透明意味着展示思维过程 | 修正：展示选择的动作、可检查的理由与结果 | Core 不要求取得或保存模型隐藏思维链 |

## 已核对的基础资料

Anthropic 建议从简单方案开始，用评估证明额外复杂度，并认真设计工具接口。这支持
本项目的“小路径先闭合”选择，但没有替本项目选定 LangChain、微服务或向量数据库。
见 [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)。

ReAct 研究了交错推理与动作、从环境获取反馈的方法。这里借鉴“读取真实反馈再继续”
的方向；论文的任务表现不能推出某套科学工具在中断时的执行保证。
见 [ReAct 原论文](https://arxiv.org/abs/2210.03629)。

MCP 工具规范提供工具描述、输入输出与发现、调用的标准表达；工具注解属于提示，
不能作为可信授权或执行效果证明。它可承担传输边界，原生状态与执行保证仍须实际
Owner 实现。见 [MCP Tools，2025-11-25 规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)。

这些资料支持设计取舍，不证明 Rho 新 Core 的实现或性能。报告里的 MemAgent 能力、
RLHF/RLAIF 比较、68 种风险、SkillSpector 效果、所谓内嵌工具消除外部延迟等说法
尚无本次核实证据，不进入架构约束。上下文容量、训练方法和某个框架的流行程度
也不能直接决定科学运行时的持久化与并发语义。

## 让新增机制承担证明责任

| 要验证的问题 | 最小实验 | 通过标准 |
| --- | --- | --- |
| 无快照模块还能取得可靠材料吗 | 连续读取临时文件，其间用外部工具修改 | 新读取得当前内容，旧材料不被悄悄替换；读取不自动记账 |
| 是否需要独立操作网关 | 单路径夹具执行，注入重复送达及回报丢失 | 原请求可定位，重复送达不重派发，未知不伪装为成功 |
| 是否需要更复杂存储 | 在受理、派发和结果保存前后中断 | 各崩溃窗口结果诚实，不把重启变成自动重跑 |
| 工具说明能被 Agent 使用吗 | 一个真实客户端用最少描述完成读取和结果定位 | 正确选择工具、参数与续读；记录具体失败再改接口 |
| 是否引入检索、框架或编排 | 与更小的方案比较同一组选定任务 | 额外机制带来可测量的任务收益，且成本与故障可解释 |

不沿用报告的统一“允许 5% 下降”或“拦截率超过 90%”。冲突覆盖、重复执行和越界
读取等正确性条件必须逐个满足；性能和成功率需要明确任务集、基线、测量方法与
适用范围后才制定目标。这些实验嵌入对应里程碑，不增加一套先于功能的评估平台。
