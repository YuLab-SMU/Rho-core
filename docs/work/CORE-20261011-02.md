- 直接调用基线（2026-10-11T01:09 前后实测，macOS）：
  - 每次调用一个进程：现有评估调用器（一个进程持有一个 Core）提交 `hold` 后进程随输入结束退出，
    下一进程查到 `Finished { exit: Signal(15) }`、取消原因 `Shutdown`。调用进程退出即停止运行，不能跨调用持有。
  - `nohup sh job.sh &` 执行两次：派发 2 次；没有请求身份、去重、输出保留或停止确认。
- Core 增加的保证（本接入层只暴露，不改语义）：一个常驻宿主持有 Core，运行的持有与调用进程无关；
  CLI 只转发请求，宿主不在时不在本进程内启动任何运行；回复丢失明确报告未知，同身份重发得到原受理。
- 可观察完成条件：经 CLI 运行真实脚本、读回真实输出与产物；CLI 进程退出后运行继续，另一调用找回同一
  run_id；多个 CLI 进程并发同身份提交只派发一次；取消经宿主送达 SIGTERM；宿主 SIGKILL 后重启找回记录不重派；
  宿主未运行时提交失败且无派发；第二个宿主不能接管已在用的 state_dir 或删除其套接字；超限请求与连接被明确拒绝。
- 最小结构与依赖：同一 package 内的二进制 `src/bin/rho-core/`（入口与参数、宿主、客户端、内部线协议），
  只用库的公共 API 与已有依赖（libc、serde、serde_json），不新增依赖；Core 库不依赖它。

## 实际交付与验证

- 实际完成：
  - `src/bin/rho-core/main.rs`：子命令分派、`--flag value` / `--flag=value` 解析与面向 Agent 的用法说明
    （命令、身份规则、退出码 0–4 的含义与下一步）。
  - `src/bin/rho-core/host.rs`：`serve` 先打开 Core（取得 state_dir 锁）再替换残留的套接字文件（只替换套接字），
    绑定 `state_dir/host.sock` 并设 0600，打印就绪行；接受线程按连接上限保留槽位，超限回答 `busy`；
    每个连接检查对端 uid、发就绪问候、读一行有界请求、调用 Core、回一行 JSON。运行视图、摘要、带来源的记录
    （输出块列表改为块数）、输出块（UTF-8 截断留待下次读取）与各类错误转为 JSON，时间写为 UTC RFC 3339。
    SIGTERM/SIGINT/SIGHUP 经处理函数写入 close-on-exec 管道，主线程读到后停止接受、删除自己的套接字、
    `Core::shutdown()`、最多等待 2 秒并打印停止报告；启动时已忽略的信号保持忽略。

- 发现并修复的问题：首版宿主用 `pthread_sigmask` 屏蔽 SIGTERM 并以 `sigwait` 接收。新回归
  `cancel_through_the_host_ends_the_run_with_sigterm` 失败：取消后运行直到 `stop_grace`（10 秒）后 SIGKILL
  才结束，`exit: Signal(9)`，`kill_sent_at` 非空；`a_terminated_host_stops_its_runs_and_removes_its_socket`
  同样得到 `Signal(9)`。查阅本机 Rust 标准库源码（`sys/process/unix/unix.rs`）确认 `Command` 有意继承父进程
  屏蔽字（只重置 SIGPIPE），先前“标准库会重置屏蔽字”的假设错误。改为处理函数加管道后两项通过。
  同时修复宿主自身错误（请求过大、无法解析）未包在 `{"ok":false,…}` 中的问题（回归首次运行时发现）。
- 回归：`tests/host.rs` 9 项，均用真实宿主进程与独立客户端进程：跨调用提交（标准输入脚本与参数）、找回、
