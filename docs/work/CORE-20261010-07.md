### 缺陷依据与实现

- 旧版基线 `cargo test --locked` 通过（16 行为回归、12 重启条目，含宿主入口），未覆盖新缺口。
- 修复前实际复现两项失败：损坏记录的 `lookup` 被报为 `NotFound`；子任务关闭继承的 stdin 后继续运行，宿主崩溃后却被便利状态当成终态。新增行为回归在旧实现上失败，在本次实现上通过。
- 源码还显示输出计数只随最终 outcome 保存、信号发送错误未核对。现由 [OperationRecord](../../src/record.rs) 独立表达派发、执行、取消、两路输出、组释放、锁观测与删除保护；便利状态仅作投影。
- [OperationStore](../../src/store.rs) 使用 SQLite WAL / FULL / fullfsync 和独立事实事务；事务内检查唯一键与全局记录容量。脚本及最大 64 KiB 的输出片段在同步后才发布引用，输出引用有配置上限。
- 缓存不隐藏损坏；未知不派发，失去原锁不证明退出。删除事务重新检查身份、版本与完成/释放事实；提交后才释放键。待保存输出的 Blob 引用受到保护，另一个操作的删除不清走这些字节。
- `list_operations(caller)` 找回该调用方的全部保留操作；示例演示重开后发现原操作和重复送达返回原受理。
- 普通查询失败不妨碍关闭真正持有的原生资源；关闭确认依据持有线程的实际结束，存储问题仍分别报告。
- [信息模型](../INFORMATION-MODEL.md)、[调用契约](../MANAGED-RUN.md)、README、隐私说明与工作规则同步到本次存储和保证范围。
