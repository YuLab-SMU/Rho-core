## Changes and retained behavior

- [Shared support](../../tests/support/mod.rs) holds bounded blocking waits,
  mode-0600 FIFO creation and request construction. Timeouts, paths, executor,
  workdir and arguments are passed explicitly; no dependencies or global state
  were added. Each fixture still owns its processes and directory/drop order.
- [Dispatch log reading](../../tests/support/dispatch.rs) returns read errors.
  Fixtures that previously permitted a missing log still do so; storage checks
  that required a readable log still unwrap the result. Native PID strings and
  dispatch counts remain checked.
- [Restart experiments](../../tests/restart.rs) share six identical default-host
  preparations: start, wait for native readiness, wait for submit acknowledgement,
  kill and reap. Injected faults, gate-release ordering and scenario-specific
  preparation remain in their tests. Native PID parsing and stdout reads also
  share local helpers, retaining their original read limits.
- [Managed-run checks](../../tests/managed_run.rs) use an ordered table for the
  three conflicting requests. All three errors are collected before checking
  them, preserving the original submit/assert order. The finished/group-release
  predicate is shared without changing the expected state.
- [Storage checks](../../tests/storage.rs) share scalar SQL reads, stdout byte
  reads, strict dispatch counts and existing-submission assertions. SQL strings,
  typed columns, returned run IDs and output bytes remain checked.
- [Host/CLI checks](../../tests/host.rs) reuse identical argument arrays, including
  the stdin submission repeated after completion. Every call still starts an
  independent CLI process; Host ownership and cleanup are unchanged.
