## 开放问题

- **活动流继续服务独立的观察消费者。** Rho 已接入 `agent.activity.read/capture/outputs`；
  不要求外部动作成为受管运行。进一步格式变动仍由真实消费者决定。
- **活动流与受管运行的显式关联。** 活动流目前只经同一状态目录关联到项目；被观察的
  Agent 会话里由 Core 发起的运行，没有 API 把 stream 和 operation 挂钩。2026-10-25 的
  评审指出了这一点，是否需要由真实消费者决定。
- **已知、暂不处理的代价**（2026-10-25 评审，都在当前上限内有界）：`read_activity` 每加入
  一条事件就重新序列化整页（每页至多 128 条、256 KiB）；淘汰时逐条重算聚合；插件的
  watch 模式每次全量重读源文件（至多 32 MiB、32768 条）。真实来源让读取或采集延迟成为
  问题时，先测量再优化。插件按 `JSON.stringify`、Core 按 serde 计算批字节，极端的浮点
  格式下可能相差几个字节；失败方向是安全的（整批拒绝），出现实际拒绝时再统一度量。
- **R 批分析**：现有的 Rscript、RDS、manifest 与普通文件已承载真实领域流程，还没有证据
  需要新的会话平台或注册表；科学产物的完整性、来源与取回由插件 Owner 决定。
- SDK、HTTP/MCP 入口与应用集成在出现真实消费者时再选。
