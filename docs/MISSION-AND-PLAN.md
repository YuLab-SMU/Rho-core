# Rho Core：从零重建的使命与实施计划

设计基线：2026-10-09。本文件规定目标、取舍与验收；它不描述已经存在的新接口。
分支与交付状态见 [README](../README.md)，最小调用路径见
[Architecture](ARCHITECTURE.md)，审核输入与判断见 [Audit decisions](AUDIT-DECISIONS.md)。

## 从研究工作出发

研究者或外部 Agent 打开一个已有项目，读取数据与代码，修改脚本，运行选定分析，
检查对象和产物，再依据反馈继续。文件可能被其他工具修改，程序可能仍在运行，
某次回报可能丢失；这些情况应当能被具体处理，而不要求先建立全项目状态模型。

Core 的价值在于让这些真实动作容易调用、结果容易理解、继续工作容易定位。
执行成功不证明分析正确，记录完整也不证明外部世界完整。观察、动作回报和科研解释
各自表达自己的范围；信息不足时允许继续取得材料和开展无关工作。

这次重建按必要用户行为重新选结构。旧 crate、OperationGateway、QuerySnapshot、
catalog、SDK 类型与职责搬迁路线不约束新架构。旧代码可以帮助理解具体失败，但
不能以现成实现、历史测试或沉没成本为理由保留整个子系统。

## 第一版要支持的动作

| 用户动作 | 可观察的结果 | 必须处理的失败 |
| --- | --- | --- |
| 按当前问题发现并读取工具 | 得到用途、参数和可直接使用的入口；已知工具无需先走完整目录 | 不存在或不支持的入口明确返回，不能暗中改目标 |
| 读取项目文件或已有运行信息 | 得到真实材料、读取范围与必要限制；较大内容可以继续读取 | 外部改变、忙碌、缓存、部分结果与不可用分别说明 |
| 修改已经读过的脚本 | 修改指定文件；返回实际写入结果 | 冲突覆盖拒绝后原字节保持，调用方草稿仍可保留 |
| 运行明确选定的代码 | 得到一次执行的身份、状态和结果入口 | 重复送达找回原请求；有意再次执行使用新身份 |
| 回报丢失后继续 | 找到原请求与已知结果，或明确结果未知；无关读取继续 | 不因重连、超时或模型猜测自动重跑 |
| 中止或结束运行 | 看到取消请求与原生停止是否确认，能定位未结束的资源 | 关闭连接不能被当成任务终止或回滚 |

第一版服务单用户、用户选择的本地项目，优先无界面交付。Core 独立验收时使用最小
协议夹具；Files 与 R 等真实科学能力由对应 Owner 的后续集成验收证明。上表不要求
一次实现整个产品，也不要求先改其他仓库。

## 责任划分

| 参与方 | 承担的责任 |
| --- | --- |
| Core | 描述已接入的工具、传递调用、管理自身受理的执行、保留找回结果所需的最小记录 |
| 领域适配器 | 接触真实文件、会话、进程或任务；检查原生条件；报告结果、范围与局部失败 |
| 外部 Agent 或普通客户端 | 目的、计划、工具选择、提示、上下文取舍、对话与停止策略 |
| 研究者 | 问题与方法的取舍，解释、复核及科研主张 |
| 应用与插件产品 | 视图、编辑器、交互状态、科学功能和选定组合的真实用户流程 |

同一公开能力服务人和 Agent。Core 不设置一套额外的 Agent 审批。调用方授权已经
成立后，只检查该动作必要的目标、请求与原生条件。近期不建设角色、逐工具授权向导、
全局风险评分或多用户策略引擎；远程与多用户需求明确时，再补对应部署边界。

Skills 可作为调用方的使用说明，Loop 是调用方利用反馈继续工作的方式，Graph 是
调用方对显式记录关系的视图。三者都不要求 Core 增加加载器、模型循环或图运行时。
工具文档要渐进可读，结果能给出具体的后续读取入口；这是接口质量，不是新状态模型。

## 最小结构与取舍

先做一个本地进程内的工具调用路径。公开入口调用同一分派函数，连接声明的领域
适配器；需要持续运行的动作才创建执行句柄与必要回报记录。逻辑职责可以分离，
不据此预建多个 crate、微服务、消息队列或持久化系统。

| 需求 | 初始选择 | 增加复杂度的证据 |
| --- | --- | --- |
| 工具发现和调用 | 简短目录、按需说明、明确参数与结果；复用标准传输 | 某个真实客户端无法表达选定调用，才扩展最小契约 |
| 当前材料 | 直接读取真实 Owner，结果有界；不自动存每次查询 | 确有历史引用或复核用途时，保存那份材料与必要来源 |
| 长运行与断线 | 原生句柄、Core 自己的执行身份、有限状态与回报 | 两个真实流程缺少相同继续语义时，才提取公共实现 |
| 持久化 | 使用成熟本地存储完成最小受理和结果记录 | 在故障实验中证明单文件或数据库方案的取舍，再选型 |
| 文件与代码编辑 | 真实文件、Git、成熟编辑组件；并发检查由实际写入 Owner 完成 | 普通工具无法保护一个具体编辑成果时，选择对应补充能力 |
| 科研会话 | 领域 Owner 管理原生状态与串行条件 | 不同语言的真实需求一致时，才抽取最小共享部分 |
| 记忆、检索、计划 | 使用外部 Agent 已有能力 | 核心工作流有无法替代且可测量的缺口时，另立需求 |

不默认建设向量数据库、Observation Store、全局版本、世界模型、通用恢复引擎、
知识图谱或永久不可变记忆账本。也不以“使用 LangChain”或“接入某种沙箱”代替
说明当前动作如何完成。具体语言、框架和库版本在首个实现里程碑中通过小实验选定。

## 必须保留的工程事实

- 模型上下文是选择过的材料，不能证明当前文件、会话或任务仍处于同一状态。
- 已读内容与准备覆盖的内容可能不同。写入 Owner 必须说明并发修改窗口、实际保证
  与拒绝行为；仅有一次哈希比较不能宣称与外部编辑器实现了原子比较后写入。
- 一次明确请求的重复送达与新的运行是不同意图。客户端代为保存请求身份，避免让
  研究者手工管理；无法定位原动作时返回未知，不能通过代码相似度推断意图。
- 受理记录、原生副作用与结果存储无法天然成为一个跨系统事务。日志不能保证
  exactly-once，也不能回滚已发生的文件修改、网络请求或科学计算。
- 取消请求、取消确认、任务结束和回滚分别说明。断线后已受理工作仍由其执行方管理；
  结果未知只限制依赖该结果或资源的动作，不能封锁整个项目。
- 只在确有继续、比对或复核用途时保存确切材料；保留路径或摘要不等于保留源字节。
  来源与时间未知时保持未知，当前观察不能补造历史归因。

这些事实约束行为，不要求复建旧执行状态机。实现只保留能够解释具体保护作用的
检查与记录；补存已取得的回报、重连原生任务和重新执行分别设计。

## 分阶段实施与完成条件

| 阶段 | 有界交付 | 通过条件 |
| --- | --- | --- |
| 0：文档基线 | 归档旧源码，重写目标和选题规则 | `main` 仅保留设计、政策与仓库元数据；归档包含原完整受控源码；其他仓库不变 |
| 1：最小读取 | 一个公开调用入口、工具说明、协议夹具、必要输入输出契约 | 在临时项目读取真实文件；大结果有明确边界与继续方式；错误目标拒绝；重复读取不产生执行记录、不启动或恢复领域运行时 |
| 2：一次受管动作 | 请求身份、实际 Owner 条件、最小受理与结果记录 | 同一身份同一请求只派发一次；同身份不同请求拒绝；记录写入失败时不派发；新身份能够有意再执行 |
| 3：运行与继续 | 长运行句柄、结果读取、取消和重连语义 | 断开等待不重跑、不误报停止；原生执行后回报未保存时保留未知；原请求可定位；重启后不自动重新派发；独立读取继续 |
| 4：可接入契约 | 最小领域接入协议、首个外部 Agent 入口、独立公开依赖 | 普通客户端和 Agent 走同一路径；适配器不读 Core 私有存储；Core 构建不依赖相邻源码；第二个入口仅适配传输 |
| 后续：选定集成 | 另行选择 Files、R 及应用消费者 | 用真实 Owner 验收读取、冲突写入、运行和产物；明确选定 SDK 与组件；单仓夹具不能代替产品通过 |

阶段 1 可先以静态接入或一个已声明子进程演示边界，不预先实现包目录、安装、
热重载、依赖解析、视图协议和插件商城。阶段 4 的实际机制由前面已经暴露的接入
需要决定。每阶段结束时更新设计中受影响的决策，分别报告目标、实现和执行证据。

## 验证方式与资源边界

每项任务先写用户动作、应观察到的结果、一个真实失败和失败后怎样继续，再实现。
测试检查实际字节、派发次数、原请求与结果；不以 crate 数、枚举数或旧目录形状验收。
持久化选择通过“受理前失败、派发后中断、结果写入失败、重复送达、进程重启”实验
验证；不要求建立通用故障平台。Core 故障实验使用夹具，科学执行另用真实 Owner。

首个相关里程碑必须为请求、读取与输出、并行执行、排队、等待及记录存储定义限额。
每个限额写清默认值、可配置处、拒绝或分页行为；待测量前不沿用旧常数，也不默认
无限。正确性是硬条件；延迟、内存、存储增长和工具描述的可用性用实测比较，审核
报告中的“5% 损失”或“90% 拦截率”不是本项目验收门槛。

新增框架或状态机制先与更小方案比较。只有实际任务效果、故障处理或维护成本有
可说明的收益，才进入必需路径。短期优先让一段真实工作闭合，不为未来规模预建云
基础设施，也不把全项目证据完整、科学有效性评分或另一套权限配置变成执行前置条件。
